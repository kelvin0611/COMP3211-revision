Mock Q21 · Software Process · 15 分 · 對應 L2、L3 · P3

(1) Explain change anticipation and change tolerance, and state which of system prototyping and incremental delivery supports each. (<100 words, 5 points)

參考答案
答案Change anticipation: the process includes activities that predict possible changes before significant rework is needed, e.g., a prototype shows key features to customers early. Change tolerance: the process is designed so that changes can be made at relatively low cost, normally through incremental development where a change only affects increments not yet built. System prototyping supports change anticipation only; incremental delivery supports both, because users try early increments (anticipation) and later increments can absorb changes cheaply (tolerance).

約 85 字 · 記法：prototype = 預早估；increment = 預早估 + 改得平。

(2) A company's projects succeed only when certain experienced developers are on the team, and every project follows its own way of working. 1) Which CMMI maturity level is the company most likely at? 2) What must the company achieve to reach level 3? (<80 words, 4 points)

參考答案
答案1) Level 1, Initial: processes are ad hoc, undocumented and depend on individual heroics, so success is unpredictable. 2) It must first plan, track and control processes at project level (Level 2, Managed), and then standardize processes across the whole organization with a common process framework and training (Level 3, Defined), so that performance is consistent whichever team does the work.

約 65 字

(3) For each XP practice, name the agile principle it supports: A) small releases B) on-site customer C) sustainable pace D) simple design E) continuous integration. (5 points)

參考答案
答案A → incremental delivery (也可以答 embrace change)；B → customer involvement；C → people not process；D → maintain simplicity；E → embrace change。

出處：L3「Support for Agile Principles in XP Practices」。Small releases 喺 lecture 同時支持 incremental delivery 同 embrace change，答 incremental delivery 最穩陣。

(4) What is the difference between the product backlog and the sprint backlog? (<40 words, 1 point)

參考答案
答案The product backlog lists all outstanding work for the whole project and is reprioritized by the product owner; the sprint backlog is the subset selected for the current sprint and is fixed once the sprint starts.
Mock Q22 · Requirements · 12 分 · 對應 L4 · P4

(1) For a food delivery app, write one functional requirement and one non-functional requirement concerning performance. Use "shall" and make both verifiable. (<80 words, 4 points)

參考答案
答案FR: The app shall allow a logged-in customer to cancel an order free of charge if the restaurant has not yet accepted it, and shall then show the order status as "Cancelled".
NFR (performance): The app shall display the restaurant search results within 2 seconds for 95% of searches when up to 5,000 users are online at the same time.

記法：FR = 系統「做咩」；NFR = 「做得幾好」，一定要有數字（時間、百分比、負載）先可以 test。

(2) A requirements document contains: R1 "The system shall respond fast." R2 "All data shall be stored only on the user's phone." R3 "Users shall be able to view their order history from any device." Identify which validation check each problem fails and explain. (<100 words, 4 points)

參考答案
答案R1 fails the verifiability check: "fast" has no measurable target, so no test can decide pass or fail; it should state, e.g., a response time limit. R2 and R3 together fail the consistency check: if data is stored only on one phone, order history cannot be viewed from other devices, so the two requirements conflict. The stakeholders must negotiate which one to change.

(3) Explain forward and backward traceability in a requirements traceability matrix, and give one reason why the matrix helps when a requirement changes. (<80 words, 4 points)

參考答案
答案Backward traceability links a requirement to where it came from (e.g., a stakeholder or a business rule). Forward traceability links a requirement to the artifacts that realize it, such as design elements, code modules and test cases. When a requirement changes, forward links show exactly which design, code and tests are affected, supporting impact analysis and controlled change propagation.
Mock Q23 · Architecture · 12 分 · 對應 L6 · P5

(1) A student puts a method showBookingDetails() that prints to the console inside the Model of an MVC system. Is this proper? Why? (<80 words, 3 points)

參考答案
答案No. In MVC the Model only manages the system data and the operations on that data; presenting data to the user is the View's job. Printing inside the Model mixes presentation with data, so the data can no longer change independently of its representation, and adding another view (e.g., a GUI) would require changing the Model. The Model should return the data and the View should print it.

同 2023 Q23(3)（printTask）一模一樣嘅套路。

(2) A city bike-sharing platform needs: i) access from phones anywhere, ii) adding more servers when demand peaks, iii) many different subsystems (payment, maps, maintenance) to share bike status data. Choose two patterns from MVC, layered, client-server and repository, and justify. (<120 words, 5 points)

參考答案
答案Client-server and repository. Client-server handles i): phone apps are clients that call services on servers over the network, so users can access the system from anywhere; it also handles ii): because services run on servers, extra server replicas can be added when load is high. Repository handles iii): bike status is kept in one central repository that payment, maps and maintenance subsystems read and update, so they do not need to know each other and the data stays consistent and is backed up in one place.

(3) A payroll system processes timesheets in batch: validate → compute pay → generate payslips. Which pattern fits best? Give one advantage and one disadvantage. (<80 words, 4 points)

參考答案
答案Pipe and filter: each stage is a filter transforming the data and passing it through a pipe to the next, which suits batch processing in separate stages. Advantage: it is easy to understand, and transformations can be reused or new ones added. Disadvantage: every filter must parse its input and unparse its output in an agreed format, adding overhead, and it is unsuitable for interactive systems.

出處：L6 pipe and filter 表（payments 系統例子）。

Mock Q24 · Class Diagram · 12 分 · 對應 L5、L8 · P1

Design the classes and draw the UML class diagram.

A cinema chain manages several cinemas. Each cinema has a name and an address and consists of several halls; a hall belongs to exactly one cinema and is identified by a hall number. Each hall has a fixed set of seats, each with a row letter and a seat number. Movies have a title and a duration. A screening shows one movie in one hall at a start time. There are two types of customers: members, who have a membership ID and loyalty points, and guests, who only provide an email. Every customer has a name. A customer makes bookings; each booking has a unique booking number, is for exactly one screening and reserves one or more seats. A customer can cancel a booking, the system can calculate the total price of a booking, and members can redeem points.

參考答案（圖 + 逐步）
{{UML:mock-cinema}}
  1. 名詞 → class：cinema、hall、seat、movie、screening、customer、member、guest、booking。「name、address、hall number」呢類只係描述嘅名詞 → attribute。
  2. 「two types of customers」→ inheritance：Member、Guest 繼承 Customer；共有嘅 name 放喺 Customer，各自嘅放子類。Customer 冇自己嘅實例，所以寫斜體（abstract）。
  3. 「consists of」+「belongs to exactly one」→ composition：Cinema ◆— Hall，Hall ◆— Seat。Hall 冇咗 cinema 就冇意義。
  4. 其他關係 → association + multiplicity：一場 screening 一套戲一個 hall（1），一套戲可以有好多場（*）；一個 booking 一場 screening、1..* 個 seat；一個 customer 好多 booking。
  5. 動詞 → operation，放喺「最識做」嗰個 class：calculateTotal() 放 Booking（佢知道有咩 seat）；redeemPoints() 放 Member；makeBooking()、cancelBooking() 放 Customer。

評分重點class 名 + attribute + operation 齊；inheritance 方向（三角形喺 parent）；composition 菱形喺 whole 嗰邊；每條線兩端都有 multiplicity。

Mock Q25 · Sequence Diagram · 9 分 · 對應 L5、L8 · P1

Identify the actors and draw a sequence diagram for the scenario.

A customer inserts a card into the ATM and enters a PIN. The ATM sends the card number and PIN to the bank server, which verifies them against the account database. If the PIN is valid, the customer enters an amount and the ATM asks the bank server to withdraw it; the server reads the balance from the account database. If the balance is sufficient, the server updates the balance and returns success; the ATM dispenses the cash and gives a receipt. Otherwise the ATM shows "insufficient funds". If the PIN is invalid, the ATM shows an error. Finally the ATM ejects the card.

參考答案（圖 + 逐步）
{{UML:mock-atm}}
  1. 搵 participant：Customer（actor，人）；:ATM、:BankServer（系統內 object）；:AccountDB（外部 database，都可以當 actor）。由左到右按「訊息流向」排。
  2. 逐句變 message：主語 = 箭咀起點，動詞 = message 名，受詞 = 參數。例如「ATM sends card number and PIN to the bank server」→ ATM → BankServer：verify(cardNo, pin)。
  3. 有回覆就畫虛線 return：account、valid/invalid、balance、success。
  4. 「If…otherwise」→ alt frame，用 [guard] 寫條件，[else] 分隔。兩層 if 就兩層 alt（可以 nest）。
  5. 「Finally」→ 放喺所有 frame 之外：ejectCard() 無論如何都會發生。

(3) Why is beta testing needed even after thorough alpha testing? (<50 words, 3 points)

參考答案
答案Alpha testing happens at the developer's site, so it cannot reproduce the variety of real environments, hardware, data and usage patterns. Beta testing lets real users use the product in their own environment, revealing problems that only appear there.

(1) A bank's 25-year-old COBOL system is critical to daily business, but it has no up-to-date documentation and only two staff understand it. Recommend an evolving strategy and justify it using the two assessment factors. (<80 words, 4 points)

參考答案
答案The two factors are business value and system quality. The system has high business value (it is critical to daily operations) but low quality (outdated language, no documentation, few people can maintain it). For high-value, low-quality systems the recommended strategy is to re-engineer it to improve maintainability, or replace it if a suitable off-the-shelf system is available. Scrapping it is not an option.

(2) Give two advantages of distributed version control over centralized version control. (<80 words, 4 points)

參考答案
答案1) Backup: every developer's machine holds a full copy of the repository, so if the main server is lost the repository can be restored from any copy. 2) Offline work and cheap branching: developers can commit, branch and view history locally without a network connection, and merge later, which suits open-source projects with many independent contributors.
