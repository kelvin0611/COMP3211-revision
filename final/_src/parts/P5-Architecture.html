4. Layered architecture

一句講完

功能分成多層，每層只依賴緊貼佢下面嗰層提供嘅服務，並向上一層提供服務；最底層係成個系統都會用嘅核心服務。

一句講完

所有資料由一個中央 repository 管理，所有 component 都可以存取；component 之間唔會直接溝通，只係經 repository。

6. Client-server

一句講完

系統功能組織成由多部 server 提供嘅 service；client 係 service 嘅使用者，經網絡存取 server。都可以喺一部電腦上實作。

When used／優缺點
When usedAdvantagesDisadvantages

易錯

2025 Q23(1) · MVC · <80 words · 3 分
參考答案
答案MVC separates presentation and interaction from system data. The Model manages the system data and the operations on it; the View defines and manages how data is presented to the user; the Controller manages user interaction and passes it to the View and Model. Advantage: data can change independently of its representation, and the same data can be shown in several views consistently. Disadvantage: it adds extra code and complexity when the data model and interactions are simple.
2025 Q23(2) · Layered · <80 words · 3 分
參考答案
答案Functionality is organized into layers; each layer relies only on the services of the layer immediately beneath it and provides services to the layer above, with core services at the bottom. Advantage: an entire layer can be replaced as long as its interface is maintained. Disadvantage (performance): a service request is interpreted at multiple layers as it passes through them, which can slow the system down.
2025 Q23(3) · Client-server · 2 分
參考答案
答案Each service is a single point of failure, so the system is susceptible to server failure or denial-of-service attacks (dependability). Alternatively: performance may be unpredictable because it depends on the network as well as the system.
2025 Q23(4) · Repository vs blackboard · <50 words · 2 分
參考答案
答案In the repository model, the repository is passive: the components using it are responsible for controlling access to the data. In the blackboard model, the blackboard actively notifies components when particular data becomes available.
2025 Q23(5) · E-commerce · <150 words · 4 分
  1. Remote accessibility → client-server（多地點存取）。
  2. Dynamic load management → client-server（server 可以 replicate）。
  3. Multi-level security → layered（L6 When used 原文）。
  4. Interface management and evolution → layered（interface 唔變就可以換成層；interface 改只影響相鄰層）。
參考答案
答案The best combination is client-server and layered. i) Remote accessibility: in the client-server pattern, customers' browsers and apps are clients that access services on servers over the network from any location. ii) Dynamic load management: servers can be replicated and added or removed as the load varies. iii) Multi-level security: the server side is organized in layers, with the most critical assets such as payment and customer data in the inner layers, and security mechanisms such as authentication provided at each layer. iv) Interface management and evolution: each layer communicates only with adjacent layers through defined interfaces, so a layer can be changed or replaced without affecting the others as long as its interface is maintained.

四、Past paper 全答

2024 Q23 · 10 分 · L6

(1) Order the layers from top to bottom: a) Domain b) Presentation c) Persistence d) Application. (4 points)

參考答案
答案b) Presentation → d) Application → a) Domain → c) Persistence

理由：用戶直接接觸 presentation；application 實作 use case，用 domain 嘅業務規則同 object；domain 需要 persistence 讀寫 database。

(2) Can MVC's model, view and controller be organized into three layers of a layered architecture? (<60 words, 3 points)

參考答案
答案Not cleanly as three strict layers. In MVC the View queries the Model directly and the Model notifies the View, so View, Controller and Model do not each depend only on the layer beneath. Usually View and Controller together form a presentation layer above a Model layer, with Model-to-View notification through an abstract listener interface.

評分重點呢題冇官方答案。最穩陣係講清楚「依賴關係」：strict layering 要求只依賴緊貼下一層，而 MVC 嘅 View 直接用 Model、Model 通知 View（雙向）。答「可以」都要講條件（View 只經 Controller、通知用 interface）。

(3) One advantage and one disadvantage of layered architecture. (<100 words, 3 points)

參考答案
答案Advantage: an entire layer can be replaced as long as its interface is maintained, and when an interface changes only the adjacent layer is affected; this also supports incremental development of layers by different teams. Disadvantage: a clean separation is often difficult in practice, and performance can suffer because a request is interpreted at multiple layers.

Putting console printing in the Model couples data with one particular presentation, so the presentation cannot change independently (e.g., adding a GUI would require changing the Model), and the Model becomes harder to unit-test. The Model should provide the task data, and a View should print it.

(3) Explain what the Dependency Inversion Principle proposes instead and why. (<120 words, 5 points)

參考答案
答案DI proposes that high-level modules should not depend on low-level modules; both should depend on abstractions, such as interfaces. Moreover, abstractions should not depend on details; details should depend on abstractions. For example, instead of a PDFReader depending directly on a concrete PDFBook class, an EBookReader depends on an EBook interface that PDFBook and other book types implement. The reason is that when higher-level components depend directly on lower-level ones, they have limited reusability and must change whenever the lower-level implementation changes. Depending on abstractions decouples the layers, so low-level implementations can be replaced or extended without modifying high-level policy code.

Asm2 Q2 · Client-server 兩個 design · Asm 12 分 · L6

Give one advantage of each design. (<200 words)

參考答案
答案Design 1 (presentation and application processing on the client, database on the server – a fat client): application processing uses the computing power of the client machines, so the server only handles data management. This reduces the processing load on the server and the amount of traffic over the network, since only database queries and results are transferred, giving more responsive interaction and allowing the server to support more clients.
Design 2 (only presentation on the client – a thin client): all application logic runs on the server, so the system is simple to manage; when the application processing changes, only the server needs updating and no new version has to be installed on every client. Clients can also be lightweight devices, and business logic and data stay together on the server, which makes them easier to secure and keep consistent.

八、短答題

1. Give two advantages of designing and documenting an explicit software architecture. (<60 words)

參考答案
答案Stakeholder communication: the architecture is a high-level presentation of the system that different stakeholders can discuss. System analysis: making architectural decisions explicit allows analysis of whether the system can meet critical non-functional requirements. (Also: large-scale reuse across systems with similar requirements.)

2. Describe the pipe and filter pattern and give one situation where it is unsuitable. (<60 words)

參考答案
答案Each processing component (filter) carries out one type of data transformation, and data flows through pipes from one filter to the next, as in Unix pipes. It suits batch data processing. It is unsuitable for interactive systems, such as a word processor, where users continuously interact with the system.

3. Describe the repository pattern and give one advantage and one disadvantage. (<80 words)

參考答案
答案All data in the system is managed in a central repository accessible to all components, and components do not interact directly, only through the repository. Advantage: components are independent and changes made by one component are visible to all, with data managed consistently in one place. Disadvantage: the repository is a single point of failure, so problems in it affect the whole system.

九、常見疑問

Q：MVC 同 layered 有咩分別？
MVC 專注將 UI 同 data 分開（3 個 component，有雙向通知）；layered 係將成個系統按抽象層次分層，只向下依賴。MVC 嘅 Model 通常喺 layered 嘅下層。
Q：Repository 同 client-server 都有中央 database，有咩分別？
Repository 重點係 component 只經 repository 交換資料、互相唔知；client-server 重點係 service 分佈喺網絡上，client 經網絡用。兩者可以一齊用。
Q：2024 Q23(2) MVC 拆三層，答可以定唔可以？
冇官方答案。關鍵係講清楚依賴方向：strict layering 只可以向下依賴，而經典 MVC 有 View→Model 直接 query 同 Model→View 通知。講到呢點，加上點樣改先可以分層，就有分。
Q：Thin／fat client 考唔考？
呢兩個名出自 L12，Max 講咗 L12 唔考。但 Asm2 Q2 嘅問題（layered 系統點樣分去 client／server）用 L6 嘅 layered + client-server 已經答到，所以概念卡 11 保留做參考。
