一、點考

一分鐘重點
  • Class diagram 4 年都有考（9、14、18、10 分）：俾你一段文字，叫你畫 class、attribute、operation、association 同佢嘅類型。
  • Sequence diagram 考過 2 次（2022 14 分、2025 9 分）：俾你一段情境，叫你搵 actor，畫訊息次序。
  • 評分重點：class 名、attribute、operation 齊；關係類型（association／aggregation／composition／inheritance）同 multiplicity 啱。其他（visibility、type）係 optional。

Class diagram 答題步驟

  1. 圈名詞（noun hunt）：每個名詞係候選 class。描述性嘅名詞（name、ID、price）變 attribute；「system」「record」呢類軟件字眼刪走。
  2. 搵「two types of」「either…or」 → generalization（inheritance）。共有 attribute 放 parent，各自嘅放 child。
  3. 搵「consists of」「has」「contains」 → 判斷 composition（同生同死、只屬一個）定 aggregation（可以獨立存在）；其他關係用普通 association。
  4. 寫 multiplicity：每條線兩頭都寫。逐句問「一個 A 有幾多個 B？一個 B 有幾多個 A？」
  5. 圈動詞 → operation，放喺「擁有相關資料」嗰個 class（Information Expert）。
  6. 最後檢查：題目每句都有對應（「Your design should support all the requirements」）；三角形喺 parent、菱形喺 whole。

Sequence diagram 答題步驟

  1. 搵 participant：人 = actor（公仔）；系統同 database = object（方框，名加底線，例如 :LMS）。題目叫你「identify the actors」，記得寫出嚟。
  2. 由左到右排：發起者最左，按訊息第一次出現嘅次序排，減少箭咀交叉。
  3. 逐句變 message：主語 → 箭咀起點；動詞 → message 名；受詞 → 參數。有回覆就加虛線 return。
  4. 條件同重複加 frame：if／otherwise → alt；if 冇 else → opt；for each → loop。Guard 寫喺 [ ]。
  5. 檢查次序：時間由上到下；建立新 object 用 «create» 虛線箭咀指去個 object 方框。

二、筆記：由零講起

一分鐘重點
  • Model 係系統嘅抽象（abstraction），唔係另一個版本；UML 係畫 model 嘅標準語言，有 14 種圖（7 structure + 7 behavior）。
  • 四個角度：context（系統同環境）、interaction（use case、sequence）、structure（class）、behavior（activity、state）。
  • Class diagram 6 種關係：dependency、association、aggregation、composition、generalization、realization。
  • Sequence diagram：lifeline、message、return、activation，同 loop／alt／opt frame。

1. System modelling 同 UML：點解要畫圖

一句講完

System modelling 係為系統整抽象 model：故意忽略細節，只留低某個角度需要嘅資訊。UML（Unified Modeling Language）係業界標準嘅畫法。

📑 Lecture 原 slide（4 張）＋逐張點睇（撳開）
點解要咁做

一個系統太複雜，一幅圖講唔晒，所以要由唔同角度各畫一幅：

  • 傾偈用：草稿、唔完整都得（agile 常用）。
  • 記錄現有系統：要啱，但可以唔完整。
  • 生成 code（model-driven engineering）：要完整又要啱。
圖解：四個角度 例子

網上書店：context model 畫書店同 payment system、物流系統點連；use case 畫顧客可以做咩；class diagram 畫 Book、Order、Customer；state diagram 畫一張 order 由 Pending → Paid → Shipped。

易錯

「Model 係系統嘅另一個完整表示」係錯：model 係 abstraction，刻意省略細節。另外 UML 有 14 種圖（7 structure + 7 behavior），但研究話大部分人用 5 種已經夠。

2. Class 同 object；class 方框點寫

一句講完

Class 係藍圖（blueprint），定義 attribute（state）同 operation（behavior）；object 係用藍圖整出嚟、喺記憶體入面有實際數值嘅實例（instance）。

📑 Lecture 原 slide（2 張）＋逐張點睇（撳開）
點解要分三格

Class 方框分三格：名、attribute、operation。咁樣一眼睇到「佢知道啲咩」同「佢識做啲咩」。只有 class 名係必須，其他可以省略。

圖解：Octopus class
符號意思
-private（只有自己用到）
+public
#protected（自己同子類）
/derived（可以由其他 attribute 計出嚟）
底線static（屬於 class，唔屬於個別 object）
斜體 class 名abstract class
例子：Class ≈ type，object ≈ variable

好似 int x：int 係 type（class），x 係 variable（object）。Octopus card1 = new Octopus()：Octopus 係 class，card1 係 object，佢嘅 amount 可能係 150.5。

易錯

考試題目通常寫明「attribute types 同 operation parameters 係 optional」（Asm2 甚至話唔好寫 type），所以寫 price 就夠，唔使 - price: double。但 operation 一定要寫，冇寫會扣分。

3. 六種關係（考試最重要）

一句講完

Class 之間嘅線分 3 類：一般（dependency）、object 層面（association、aggregation、composition）、class 層面（generalization、realization）。

📑 Lecture 原 slide（4 張）＋逐張點睇（撳開）
點解要分咁多種

唔同嘅線表達唔同嘅「關係強度」：由弱到強係 dependency（用一用）→ association（認識）→ aggregation（擁有，但可以分開）→ composition（擁有，同生同死）。Generalization 就係 is-a（「係一種」）。

圖解：6 種線點畫
關係畫法意思關鍵字
Dependency虛線 + 開口箭咀A 改，B 可能要跟住改（例如 Game 用 Clock）uses、depends on
Association實線兩個 object 互相認識、可以溝通has、works for、places
Aggregation實線 + 空心菱形（喺 whole 嗰頭）part-of；part 可以屬幾個 whole，可以獨立存在contains（但可以分開）
Composition實線 + 實心菱形（喺 whole 嗰頭）強 part-of；part 只屬一個 whole，同生同死consists of、cannot exist without
Generalization實線 + 空心三角形（喺 parent 嗰頭）is-a；子類繼承 parent 嘅 attribute 同 operationtwo types of、kind of
Realization虛線 + 空心三角形class 實作 interfaceimplements
例子：逐個判斷
  1. 「Each building consists of rooms」：房冇咗棟樓就冇意義 → composition，◆ 喺 Building。
  2. 「A curriculum includes courses」：一科可以喺幾個 curriculum，curriculum 取消咗科目仍然存在 → aggregation，◇ 喺 Curriculum。
  3. 「Students are persons」→ generalization，△ 指向 Person。
  4. 「A person works for companies」→ 普通 association。
易錯

菱形同三角形畫錯邊係最常見錯：菱形永遠喺「整體」（whole）嗰頭；三角形永遠喺「parent」嗰頭。拿唔準 aggregation 定 composition，就問：「whole 冇咗，part 仲存唔存在？」存在 → aggregation。

4. Association 同 multiplicity

一句講完

Association 表示兩個 class 嘅 object 會互相認識；multiplicity 寫喺線兩頭，講「對面每一個 object 對應我呢邊幾多個」。

📑 Lecture 原 slide（3 張）＋逐張點睇（撳開）
點解重要

Multiplicity 就係業務規則：「每個客至少一個戶口」、「一張 order 至少一個 item」。寫錯 multiplicity 等於理解錯 requirement，係考試必扣分位。

圖解：L5 嘅三個例子
寫法意思
1剛好 1 個
0..1冇或者 1 個
* 或 0..*任何數量（包括 0）
1..*至少 1 個
1..21 至 2 個（例如 shared account 最多 2 個 owner）
例子：點樣讀
  1. City —— Country（is capital of）：City 旁邊寫 1，Country 旁邊寫 0..1。
  2. 由 Country 出發問：「一個 Country 有幾多個首都 City？」→ 睇 City 旁邊 → 1。
  3. 由 City 出發問：「一個 City 係幾多個 Country 嘅首都？」→ 睇 Country 旁邊 → 0..1（大部分城市唔係首都）。
  4. Mother —— Child：Child 旁邊 1..*（一個媽媽有 1 個或以上仔女），Mother 旁邊 1（每個仔女剛好 1 個媽媽）。
  5. Person —— Company（works for）：兩頭都係 *（一個人可以打幾份工，一間公司有好多員工）。

記法「我有幾多個你」→ 寫喺「你」旁邊。由 A 行過去 B，數字喺 B 嗰頭。

易錯

每條線兩頭都要寫。題目講「at least one」→ 1..*，唔係 *；講「exactly one」→ 1；講「may have」→ 由 0 開始。

5. Generalization（inheritance）同 abstract class

一句講完

Generalization 表示「is-a」：子類（subclass）係 parent（superclass）嘅一種，自動繼承 parent 嘅 attribute 同 operation。

📑 Lecture 原 slide（2 張）＋逐張點睇（撳開）
點解要咁做

消除重複：Book 同 DVD 都有 id、title，就放喺 LibraryItem 一次，唔使寫兩次。之後加多種 item（例如 Magazine），只需要加一個子類。

圖解：L8 嘅 library domain model
手機睇：圖可以左右捲 ⇆
例子：由文字判斷
  1. 「There are two types of library items, i.e., books and DVDs」→ LibraryItem 係 parent，Book、DVD 係 child。
  2. 「Each library item has an ID and a title」→ id、title 放 parent。
  3. 「Each book is also associated with an ISBN」→ isbn 只放 Book。
  4. LibraryItem 本身唔會有實例（每件嘢一定係 Book 或 DVD）→ abstract，class 名寫斜體。
易錯

三角形箭咀指向 parent，唔係 child。子類唔使再寫一次 parent 嘅 attribute。「Fine」呢類可以計出嚟嘅嘢（L8：fine 由 Loan 計）唔應該做 class，做 operation 或 derived attribute。

Analysis 用 noun hunt 整 domain model（只有概念、attribute、association，冇 operation）；design 再加 operation、type、visibility，變成 design class diagram。

Domain model 係大家對「問題」嘅共同理解，同實作無關；design class diagram 係接近 code 嘅藍圖。L8 嘅金句：「A noun is earned, not invented」：requirement 冇要求嘅名詞唔好加做 class。

7. Operation 放邊個 class：Information Expert

一句講完

將一個職責交俾擁有相關資料嗰個 class（GRASP 嘅 Information Expert）；新 object 由聚合佢嘅 class 建立（Creator）。

📑 Lecture 原 slide（2 張）＋逐張點睇（撳開）
點解要咁做

規則同資料放埋一齊，改資料格式時只影響一個 class（high cohesion、low coupling）。L8 例子：fine 依賴 dueDate，dueDate 喺 Loan，所以 computeFine() 放 Loan，唔放 Catalog。

圖解：L5 lecture example
手機睇：圖可以左右捲 ⇆

  2. getSubtotal() 要 quantity × price → OrderItem 有呢兩個 → 放 OrderItem。

易錯

唔好將所有 operation 塞落一個「System」或「Manager」class（L8 叫 god class）。考試動詞例如「deposit、withdraw、check balance」要放喺 Account，唔放 Customer。

8. Use case diagram

一句講完

Use case diagram 畫系統同外面嘅 actor之間有咩互動：每個 use case（橢圓）係一個有目的嘅任務，actor（公仔）可以係人或者其他系統。

📑 Lecture 原 slide（3 張）＋逐張點睇（撳開）
點解要咁做

用嚟搵 user requirements：一眼睇到邊類用戶可以做咩。四種關係：association（actor—use case）、generalization（actor 之間或 use case 之間）、«include»、«extend»。

圖解：L5 Order Processing（簡化） 例子：include vs extend（L5 ATM）
«include»«extend»
意思base 一定要用佢先完成到有條件先加，base 自己都完成到

例子Withdraw Cash、Check Balance 都 include Authenticate UserSend Low Balance Alert extend Withdraw Cash（餘額低過門檻先觸發）

Include 同 extend 嘅箭咀方向相反，而且都係虛線。Actor 之間嘅 generalization 用實線 + 空心三角形。

9. Sequence diagram：基本元素

一句講完

Sequence diagram 畫一個情境入面，actor 同 object 之間按時間次序傳嘅訊息：橫向係參與者，縱向係時間（由上到下）。

📑 Lecture 原 slide（2 張）＋逐張點睇（撳開）
點解要咁做

Class diagram 只講「有咩 class」，sequence diagram 講「佢哋點合作完成一件事」。L8 強調兩者要一致：sequence diagram 每個 message 都要係 class diagram 某個 class 嘅 method。

圖解：L5 View Patient Information

Actor／object公仔／方框（name:Class 加底線）參與者
Lifeline向下嘅虛線參與者喺呢段時間存在
Activation窄長方形（青色）正在處理緊
Message實線 + 實心箭咀call 一個 method
Return虛線 + 開口箭咀回覆結果
例子：逐步讀
  1. Receptionist 叫 P（PatientInfo）嘅 ViewInfo(PID)。
  2. P 叫 database report(Info, PID, UID)，同時俾埋 receptionist 嘅 UID 做保安檢查。

Lifeline、activation、frame 係 L5 所講嘅「syntactic sugar」：考試最重要係 participant 齊、message 次序同方向啱、條件有 frame。Return 一定要用虛線。

10. Sequence diagram：loop、alt、opt frame 同 «create»

一句講完

Frame 係圍住一段 message 嘅方框，左上角寫類型：loop（重複）、alt（多條路揀一條，用虛線分隔）、opt（有條件先做）。Guard 寫喺 [ ]。

真實情境有 if 同 for each；冇 frame 就畫唔到「條件唔成立會點」。Frame 可以 nest（例如 loop 入面再有 opt）。

11. State diagram（behavioral model）

一句講完

State diagram 畫一個系統（或 object）有幾多個 state，同埋咩 event 令佢由一個 state 轉去另一個。

📑 Lecture 原 slide（5 張）＋逐張點睇（撳開）
點解要咁做

Behavioral model 有兩類：data-driven（資料到咗就處理，用 activity diagram）同 event-driven（有事件先反應，用 state diagram）。微波爐、ATM 呢類即時系統適合 state diagram。

圖解：L8 LibraryItem 嘅一生 例子：微波爐（L5）

Waiting →（按 Full power）→ Full power →（按 Timer）→ Set time →（門關咗）→ Enabled →（Start）→ Operation →（時間到）→ Waiting。門打開會去 Disabled（安全理由）。State 太多時用 superstate：高層圖當一個 state，另一幅圖再展開。

易錯

「due date passes」係時間觸發，唔係資料流，所以 DFD 畫唔到，要用 state machine（L8 原話）。

12. 畫完點檢查：class diagram 同 sequence diagram 要一致

一句講完

Static model（class diagram）同 dynamic model（sequence、state diagram）描述同一個設計，必須一致。

📑 Lecture 原 slide（1 張）＋逐張點睇（撳開）
點解

Sequence diagram 入面每個 message 都會變成 code 入面某個 class 嘅 method。如果 sequence 叫咗 loan.computeFine()，class diagram 嘅 Loan 就一定要有 computeFine()。

檢查清單
  1. Class diagram：題目每個名詞都有歸宿（class、attribute 或者有理由刪走）。
  2. 每條線兩頭有 multiplicity；菱形、三角形方向啱。
  3. 每個動詞都有 operation，放喺 Information Expert。
  4. Sequence diagram：每個 message 嘅接收者，喺 class diagram 都有對應 method。
  5. 條件、重複都有 frame；return 用虛線。
例子

2025 卷 Q24（class）同 Q25（sequence）都係圖書館：Q25 嘅 verifyUser、isAvailable 等 message，應該對應 Q24 class 入面嘅 operation。考試時兩題一齊諗會快好多。

易錯

唔好喺 sequence diagram 入面畫一個 class diagram 冇嘅 participant 但冇解釋；database 可以當外部 actor 或者 object，兩種都接受，但要一致。

三、完整示範：2025 Q24 圖書館（9 分）

📄 原卷題目截圖：2025 Q24 · Class Diagram（9 分）（撳開）
一分鐘重點
  • 6 個 class：Category、LibraryItem（abstract）、Book、DVD、User、Loan。
  • Book、DVD 繼承 LibraryItem；Category ◇ LibraryItem；Loan 連 User 同 LibraryItem。

A library management system tracks information about its library items, users, and the items loaned by each member. There are two types of library items, i.e., books and DVDs. Each library item has an ID and a title, and it is available if checked in or unavailable if checked out. Each book is also associated with an ISBN and a list of authors, and each DVD is also associated with a director and its runtime in seconds. The library items are organized in different categories with distinct names. People add each library item to a category when it arrives at the library, and can search for library items within a category. Each library user has a unique name and ID and can borrow/return items from/to the library. Each loan has a unique ID, and people may need to know the fine to be paid for an overdue loan.

「A university has many faculties; closing the university closes all faculties. A faculty employs many professors; a professor may work for several faculties and remains employed by the university if a faculty closes.」畫 University、Faculty、Professor 之間嘅關係。

八、短答題

1. Explain the difference between aggregation and composition, with one example each. (<80 words)

參考答案
答案Both are part-of relationships. In aggregation, a part can belong to several wholes and can be created and destroyed independently, e.g., a Course can be part of several Curricula. In composition, a part belongs to only one whole and exists only together with it, e.g., a Room is part of exactly one Building and is destroyed with it. Aggregation uses a hollow diamond; composition a filled diamond at the whole.

2. Distinguish «include» and «extend» in use case diagrams. (<60 words)

參考答案
答案«include»: the base use case always needs the included use case to complete, so common steps are factored out (Withdraw Cash includes Authenticate User). «extend»: the extension adds optional behaviour to the base use case only when a condition holds; the base can complete without it (Send Low Balance Alert extends Withdraw Cash).

3. Why must the design class diagram and the sequence diagrams of a system agree? (<50 words)

參考答案
答案They describe the same design from static and dynamic views. Every message sent in a sequence diagram is a call of a method on the receiving object, so that method must exist in that class in the class diagram; otherwise the design cannot be implemented consistently.

4. What is the difference between a domain model and a design class diagram? (<60 words)

參考答案
答案A domain model is produced in analysis: it shows real-world concepts, their attributes and associations, independent of implementation and without operations. A design class diagram is produced in design: it adds typed attributes, references, operations and visibility, forming a blueprint close to the code.

九、常見疑問

Q：Attribute 要唔要寫 type 同 visibility？
考試題目寫明「other information is optional」。寫 name 就夠；寫埋 - name: String 唔會扣分，但浪費時間。Asm2 更加要求唔好寫 type。
Q：Aggregation 定 association 分唔清點算？
題目冇「part of／consists of／contains／has a group of」呢類字，就用普通 association。有呢類字，再問「whole 冇咗，part 仲喺唔喺度」：喺 → aggregation，唔喺 → composition。
Q：Multiplicity 寫喺邊頭？
「一個 A 有幾多個 B」嘅答案寫喺 B 旁邊。逐條線用兩句問自己：一個 A 對幾多個 B？一個 B 對幾多個 A？
Q：Database 喺 sequence diagram 係 actor 定 object？
兩種都接受。佢喺系統外面就當 actor（公仔）或者外部系統方框；最重要係畫咗，同埋 message 次序啱。
Q：要唔要畫 activation 長方形？
L5 話係 syntactic sugar，唔畫唔會扣主要分。時間夠先畫。
Q：題目話 operation 要「support all requirements」，點先算夠？
逐句搵動詞：update、place、add、search、borrow、return、deposit、withdraw、check、write……每個動詞都要喺某個 class 有對應 operation。冇動詞嘅 class 都可以加 getter，但唔係必須。
Q：Abstract class 點表示？
Class 名寫斜體，或者加 «abstract»。手寫時寫 «abstract» 最清楚。
